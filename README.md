# Airlines frontend

Svelte 5, TypeScript, Vite, Tailwind CSS и Lucide. Единый светлый стиль, список
прогонов и отдельная страница с именем, описанием и статусом. Доступны создание,
редактирование имени/описания и удаление с подтверждением.

## Разработка

Требуется Node.js 24.

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. По умолчанию прокси Vite обращается к
**реальному API проекта**: сохранение и удаление из локального интерфейса меняют
серверные данные. Для локального core скопировать `.env.example` в `.env.local`
и указать `API_PROXY_TARGET=http://localhost:8080`.

Маршрут `/` — главная проекта. В `/runs` отображаются список прогонов слева
и приглашение выбрать прогон справа; `/runs/{id}` открывает выбранный прогон.
На телефоне список и выбранный прогон показываются отдельными экранами.
В режиме разработки `/preview/runs` показывает локальные примеры всех статусов.
Создание, изменение и удаление в этом режиме происходят только в памяти браузера;
при перезагрузке примеры восстанавливаются. Запросы к API не отправляются.
Демонстрационные данные не входят в production-сборку.
API вызывается по относительному пути `/api/core`, без браузерного CORS.
Имя — от 1 до 120 символов, не из одних пробелов; описание — до 2000 символов.
Пустое описание при редактировании отправляется как `null`.

## Проверки

```sh
npm run format:check
npm run check
npx playwright install chromium
npm test
npm run build
```

Два браузерных сценария проверяют CRUD, валидацию, сетевую ошибку с повторной
загрузкой и мобильную вёрстку. Все запросы API в тестах перехватываются,
рабочая база не используется.

## CI/CD

GitHub Actions проверяет форматирование, типы и браузерные сценарии, собирает
статические файлы и публикует образ в GHCR. Для `main` job `deploy` автоматически
разворачивает проверенный образ по digest из того же запуска в окружении
`production`, без ручного подтверждения. Запуски для `main` выполняются последовательно.
SSH-ключ и known hosts хранятся в secrets окружения, host/user — в его
variables. Серверные заметки и локальные секреты в репозитории не хранятся.

Для первой выкладки требуется маршрут корня домена к frontend в конфигурации
шлюза проекта. Последующие деплои frontend и core независимы.
